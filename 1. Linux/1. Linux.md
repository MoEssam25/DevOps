# 1. What is an Operating System (OS)?

An ****Operating System**** is the core software layer that:

- Manages the computer's ****hardware**** (CPU, RAM, disk, devices)
- Manages ****software resources**** (processes, files, memory)
- Provides ****common services**** that all programs use (printing, networking, file access, drawing windows)

****The key idea — abstraction:**** The OS acts as a layer between applications and the hardware.

```
┌─────────────────────────┐  
│   Applications          │  (Chrome, VS Code, ...)  
├─────────────────────────┤  
│   Operating System      │  ← abstraction layer  
│   (Windows / Linux /    │    - isolates apps from each other  
│    macOS / Android)     │    - hides hardware complexity  
├─────────────────────────┤  
│   Hardware              │  (CPU, RAM, disk, screen, network card)  
└─────────────────────────┘
```

Without an OS, every program would need to know how to talk to every piece of hardware directly. The OS gives programs simple, standard interfaces instead (e.g., "write this file") and handles the messy hardware details itself.

****Isolation:**** Each app runs in its own protected space. If Chrome crashes, it doesn't take down VS Code — the OS enforces this separation.

# 2. Main Functions of an OS

### 2.1 Process Management (CPU)

- A ****process**** is a running program — the program's code plus its current state (variables, open files, position in execution).
- ****Key fact:**** 1 CPU core can execute ****only 1 process at a time****. The OS creates the illusion of multitasking by switching between processes thousands of times per second.
- Dual-core CPU → 2 processes truly in parallel
- Quad-core CPU → 4 processes truly in parallel
- The OS decides __which__ process runs next, __when__, and __for how long__ — this is called ****scheduling****.

### 2.2 Memory Management (RAM)

- The OS allocates RAM to each running process and protects one process's memory from being read or corrupted by another.
- ****Memory swapping:**** If RAM fills up (too many apps open), the OS moves the memory contents of __idle__ processes from RAM to a swap area on the hard drive to free space for active apps. Swapping is slow compared to RAM, which is why heavy multitasking can cause noticeable lag — the disk is ~1000× slower than RAM.

### 2.3 Storage Management (Hard Drive / Secondary Memory)

- RAM is __temporary__ (lost when power goes off); the hard drive is __permanent__.
- Example: while editing a file in VS Code, your work lives in ****RAM**** for speed. When you click ****Save****, the OS writes it to the ****hard drive**** so it survives a shutdown.
- The OS also manages free space, file placement, and disk access efficiency.

### 2.4 File Management

- Files are stored in an organized structure using a ****file system****.
- The file system is organized into ****directories (folders)****, typically in a hierarchy.
- ****Unix/Linux/macOS:**** a ****single tree**** — everything starts from one root: `/`
- ****Windows:**** ****multiple root folders**** — one per drive (`C:\`, `D:\`, ...)

### 2.5 Device Management

- The OS communicates with hardware devices through ****device drivers**** — small programs that translate OS commands into the specific language each device understands (printer, mouse, GPU, network card...).
- Driver responsibilities:
- Keep track of all connected devices
- Decide which process gets a device, when, and for how long

### 2.6 Security

- Managing ****users and permissions****: each user has their own account, home directory, and permission set.
- The OS enforces rules like "this user can read this file but not modify it."

### 2.7 Networking

- Managing ****ports**** and ****IP addresses****:
- Outgoing: collects data from all apps' ports and sends it onto the network
- Incoming: receives network packets and forwards each one to the correct process/app

# 3. OS Components

### 3.1 The Kernel — the heart of the OS

- The ****kernel**** is the core program at the center of the OS; everything else is built on top of it.
- It is the ****first thing loaded at boot**** (loaded by the ****bootloader/bootstrap****).
- It provides basic services for all other parts of the OS and consists of things like:
- ****Device drivers**** → talk to hardware (I/O devices)
- ****Scheduler / dispatcher**** → decide which process runs on the CPU and when
- ****Memory manager**** → allocate RAM to processes
- ****File system**** → organize files on disk
- Main kernel jobs:
- Start processes for apps
- Allocate resources (CPU time, memory, devices) to apps
- Clean up resources when an app shuts down

****How do you "talk" to the kernel?****

- ****GUI**** (Graphical User Interface) — clicking, menus, windows
- ****CLI**** (Command Line Interface) — typing commands (e.g., Linux terminal)
- Both eventually translate your actions into ****system calls**** — the low-level requests apps make to the kernel.

### 3.2 The Application Layer

On top of the kernel sits the application layer — the user-facing part of the OS.

****Linux example — many distributions, ONE kernel:****

```
┌──────────────────────────┐  
│ Ubuntu, Mint, Debian,    │  ← App layer (distributions)  
│ CentOS, Android...       │  
├──────────────────────────┤  
│ Linux Kernel             │  ← same kernel underneath!  
├──────────────────────────┤  
│ Hardware                 │  
└──────────────────────────┘
```

All Linux distributions share the same kernel — they differ only in the apps, tools, and desktop environments bundled on top. ****Android is also Linux-based**** (its app layer is the Android framework):
```
┌──────────────────────────┐  
│ User apps (Gmail, etc.)  │  
├──────────────────────────┤  
│ Android (app layer)      │  
├──────────────────────────┤  
│ Linux Kernel             │  
├──────────────────────────┤  
│ Hardware                 │  
└──────────────────────────┘
```

- Each OS releases many versions, but the kernel architecture stays consistent.
- ****macOS and iOS**** use a different kernel called ****XNU**** (not "Linux" — this was mislabeled in the original notes).
- macOS and Linux have ****similar**** command lines and file structures (both are Unix-like). ****Windows is completely different.****

### 3.3 Client OS vs Server OS

|   |   |
|---|---|
|Client OS|Server OS|
|Runs on personal computers (laptops, desktops)|Runs on servers (always-on machines serving requests)|
|Has GUI, designed for one user at a time|Linux and Windows both have server editions; ****Linux dominates**** servers|
|Bundles user apps (browser, media player)|Lightweight and optimized for performance — often ****no GUI****, no user apps|

# 4. Why Learn Linux as a DevOps Engineer?

- ****Linux is the dominant server OS**** — most of the internet's servers run Linux.
- DevOps engineers ****work with servers constantly****: installing, configuring, monitoring, automating.
- You need Linux for: package management, scripting, permissions, networking, and Linux-native DevOps tools (Docker, Kubernetes, Ansible, Jenkins all run natively on Linux).

# 5. Virtualization & Virtual Machines (VMs)

### 5.1 What is a VM?

A ****Virtual Machine**** is a complete, software-based computer that runs __on top of__ a physical host machine. The hypervisor gives it dedicated slices of the host's real resources (CPU cores, RAM, disk space).

****Virtualization**** = creating this software-based version of a computer, using resources "borrowed" from the physical host.

### 5.2 The Hypervisor

- A ****hypervisor**** is the technology/software layer that enables virtualization — it hosts VMs on a physical machine.
- Example: ****VirtualBox**** (open source) — lets you allocate specific amounts of RAM, CPU cores, and storage to a VM.
```
┌──────────────────────────┐  
│ Guest OS (e.g., Linux)   │  ← the VM  
├──────────────────────────┤  
│ Hypervisor (VirtualBox)  │  ← allocates host resources  
├──────────────────────────┤  
│ Host OS (e.g., Windows)  │  
├──────────────────────────┤  
│ Hardware                 │  
└──────────────────────────┘
```
### 5.3 Key properties

- ****Any OS can run on any host:**** a Linux VM runs happily on a Windows machine.
- ****Complete isolation:**** a VM is partitioned from the rest of the system — it can't interfere with the host OS or other VMs. If the guest crashes or gets infected, the host stays safe.

### 5.4 Benefits of VMs

- ****Learn any OS**** without replacing your main OS — run Linux inside Windows, or Windows inside Linux.
- ****Test safely:**** experiment with apps, configurations, or even malware analysis without risking your real system.
- ****Reproducible environments:**** DevOps uses VMs (and their lighter cousin, containers) to ensure "works on my machine" becomes "works everywhere."
- One physical server can host many VMs — the foundation of cloud computing (AWS, Azure, GCP are all built on this idea).

### 5.5 Key terms

- ****Host OS**** — the OS installed directly on the physical hardware.
- ****Guest OS**** — the OS running inside the VM.

## Quick Glossary

|                      |                                                                 |
| -------------------- | --------------------------------------------------------------- |
| Term                 | Meaning                                                         |
| ****OS****           | Software layer managing hardware and providing services to apps |
| ****Process****      | A running program (code + its current state)                    |
| ****Kernel****       | Core of the OS, loaded first at boot, manages all resources     |
| ****Driver****       | Program that lets the OS communicate with a specific device     |
| ****RAM****          | Fast, temporary working memory                                  |
| ****Swap****         | Disk space used as overflow when RAM is full (slow)             |
| ****Hypervisor****   | Software that creates and manages VMs                           |
| ****Host OS****      | OS running directly on the hardware                             |
| ****Guest OS****     | OS running inside a VM                                          |
| ****XNU****          | The kernel used by macOS and iOS                                |
| ****Distribution**** | A Linux variant (Ubuntu, Debian...) sharing the same kernel     |
